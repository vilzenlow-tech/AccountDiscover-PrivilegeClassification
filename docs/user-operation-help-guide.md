# Account Discovery Tool User Operation Help Guide

This guide explains how users operate the Account Discovery Tool, what each page is for, what each scan type does, and which scan to use in common enterprise scenarios.

## Standard Operating Flow

1. Configure credentials and connectors.
2. Add or enable assets.
3. Launch or schedule scans.
4. Review accounts, findings, password policy results, and evidence.
5. Tune rules or create exceptions where the business has approved risk.
6. Use the audit log and exports for compliance evidence.

## Page-by-Page User Operations

| Page | Purpose | User operations | Use when |
|---|---|---|---|
| Login | Authenticate to the console. | Enter user credentials and access the application. | Starting any operator session. |
| Dashboard | Executive view of discovery coverage, privileged account counts, risk classes, and latest scan time. | Review metrics, last scan timestamp, privileged/dormant counts, and navigation into scans or findings. | Daily operations, management review, and quick health checks after a scheduled scan. |
| Accounts | Central inventory of discovered identities across operating systems and databases. | Filter by platform, privilege class, enabled state, or search text. Open an account for evidence. | Finding who has access, reviewing privileged users, checking dormant or shared/service accounts. |
| Account Detail | Detailed evidence for one identity. | Review identity fields, classification, risk score, rule matches, entitlements, last login, and raw evidence summary. | Validating why an account is full admin, sensitive non-admin, privileged service, or non-privileged. |
| Assets | Inventory of target systems and database instances. | Add/edit assets, set platform, hostname/IP, connector, tags, and discovery enabled status. Export inventory. | Onboarding new targets, disabling retired systems, tagging by site/application/environment/owner. |
| Asset Detail | Asset-level view of accounts, findings, and scan context. | Review accounts discovered on a host or database, linked connector, platform, and scan history. | Investigating one server/database or checking whether a target scanned successfully. |
| Connectors | Manage scan protocol connectors and credential references. | Create vault-backed credentials, create connectors by kind, assign default ports/options, and test configuration. | Configuring SSH, WinRM, or database connection methods before scanning assets. |
| Scans | Launch, monitor, schedule, retry, and manage scan profiles. | Launch scans, select profiles, collect password policies, view target status, cancel jobs, retry failed targets, seed default profiles, and create schedules. | Running discovery, troubleshooting failed targets, or narrowing scans to specific platforms. |
| Findings | Review privilege findings generated by rules. | Filter and review open findings, inspect affected account/asset context, and prioritize remediation. | Security review, weekly privileged access review, and remediation tracking. |
| Password Policy | Review password policy posture and account-level exceptions. | View policy summary, findings, exceptions, compare policies, review/export CSV or Excel reports. | Checking weak policy, password-never-expires exceptions, lockout settings, and policy drift. |
| Rules | Manage deterministic classification rules. | Review built-in rules, add/edit custom rules, and verify priority, privilege class, confidence, and risk score. | Tuning enterprise-specific admin groups, DBA roles, service naming, or exception patterns. |
| Exceptions | Manage approved suppressions and risk acceptances. | Create/edit exceptions by account, asset, group, or global scope. Track review state and expiry. | Suppressing known approved service accounts or accepted risks without deleting evidence. |
| Tags | Manage business metadata. | Create tags for application, environment, business unit, criticality, compliance, ownership, technology, or custom categories. Assign/remove tags from assets. | Scoping scans, reporting by owner/environment, and organizing large inventories. |
| Agent Connectors | Manage remote connector agents in segmented networks. | Generate enrollment tokens, approve pending agents, register placeholders, enable/disable, revoke, and open details. | Scanning remote sites, DMZs, cloud VPCs, or networks where the console cannot reach targets directly. |
| Agent Connector Detail | Inspect and control one connector agent. | Review heartbeat, health, configuration, logs, jobs, allowed scan modes, and result uploads. | Troubleshooting connector status and validating remote scan execution. |
| Audit Log | Append-only record of privileged user actions. | Review who launched scans, changed credentials/connectors/rules/exceptions, approved agents, or exported reports. | Compliance review, incident investigation, and operational accountability. |
| AI Assistant | In-app help and query support. | Ask operational questions about accounts, assets, findings, credentials, scans, schedules, and policies. | Fast navigation help or explaining results without leaving the console. |

## Scan Profiles, Purpose, and Recommended Scenarios

| Scan profile | Purpose | Recommended scenario |
|---|---|---|
| Full Scan | All enabled assets across every platform. | Baseline inventory, full refresh, post-deployment validation, or monthly enterprise review. |
| OS Scan | All operating systems: Linux, Unix, and Windows. Excludes databases. | Server access review when database accounts are handled by a separate DBA workflow. |
| Unix / Linux Scan | All SSH-based Unix/Linux platforms: RHEL, CentOS, Ubuntu, SLES, Solaris, AIX, HP-UX. | Unix team review, SSH credential validation, sudo/RBAC review. |
| Linux Scan | Modern Linux only: RHEL, CentOS, Ubuntu, SLES. | Standard Linux fleet scanning with common getent/shadow/sudoers evidence. |
| RHEL / CentOS Scan | Red Hat compatible systems only. | RHEL estate review, patch window validation, or targeted Linux troubleshooting. |
| Ubuntu Scan | Ubuntu servers only. | Cloud Linux or Ubuntu application server review. |
| SLES Scan | SUSE Linux Enterprise only. | SAP or SUSE estate review. |
| Legacy Unix Scan | Solaris, AIX, and HP-UX. | Legacy platform review where RBAC/trusted-mode evidence and specialist owners are involved. |
| Windows Scan | Windows Server/Desktop via WinRM/WMI. | Local Administrators review, service/task run-as review, RDP/remote management group review, password-never-expires checks. |
| Database Scan | All supported databases: MySQL, MSSQL, MongoDB, Oracle, PostgreSQL, Redis. | DBA access review, global role review, and database-native account inventory. |
| Relational DB Scan | MySQL, MSSQL, Oracle DB, PostgreSQL. | Traditional database privilege review across SQL engines. |
| NoSQL / Cache Scan | MongoDB and Redis. | Application platform review for document stores and cache systems. |
| MySQL / MariaDB Scan | MySQL/MariaDB accounts and grants. | Review root users, global grants, grant option, locked accounts, and password policy status. |
| MSSQL Scan | SQL Server logins and server/database roles. | Review sysadmin/securityadmin/db_owner and SQL login password policy flags. |
| MongoDB Scan | MongoDB users and roles. | Review root, userAdminAnyDatabase, dbAdminAnyDatabase, backup/restore, and inherited roles. |
| Oracle DB Scan | Oracle users, system privileges, role grants, and profiles. | Review DBA/SYS* roles, catalog privileges, locked users, and profile policy. |
| PostgreSQL Scan | PostgreSQL roles and memberships. | Review superuser, createrole, createdb, replication, pg_* built-in roles, and role validity. |
| Redis Scan | Redis ACL users and command/key-pattern permissions. | Review default user, +@all, nopass, broad key patterns, and dangerous command access. |

## Scan Modes and Job Types

| Type | Purpose | When to use |
|---|---|---|
| Safe mode | Default read-only discovery using normal metadata commands. Avoids expensive or intrusive probes. | Routine scheduled scans, production business hours, broad inventory scans. |
| Deep mode | Reserved for richer evidence where configured. May use additional probes, longer timeouts, or more complete relationship walks. | Controlled maintenance windows, targeted investigations, incomplete evidence from safe mode. |
| Collect password policies | Optional scan setting that adds password-policy probes per target. | Policy audits, password-never-expires review, weak lockout/complexity checks. |
| Manual/on-demand scan | Operator-launched scan from the Scans page. | Immediate validation after onboarding, remediation, credential fixes, or incident response. |
| Scheduled scan | Recurring scan using a selected profile and scope. | Daily/weekly production monitoring and consistent audit cadence. |
| Retry failed targets | Relaunches only failed targets from an existing job. | After fixing credentials, firewall, WinRM/SSH, or database grants. |
| Connector-agent credentialed discovery | Remote connector agent runs target scans and uploads results to the console. | Segmented networks where central console cannot directly reach targets. |
| Discovery basic | Connector-agent job that performs non-credentialed or lightweight checks where supported. | Connectivity/health validation and future low-impact inventory probes. |
| Discovery credentialed | Connector-agent job with target credentials. | Full account discovery on remote Windows/Linux/database targets. |
| Bulk scan | Job pattern for many targets or imported scope. | Large onboarding waves or estate-wide refreshes. |

## Recommended Workflows

| Scenario | Recommended operation |
|---|---|
| First-time setup | Create credentials in Connectors, create protocol connectors, add assets, assign tags, then run a small platform-specific scan before launching Full Scan. |
| Daily operations | Open Dashboard, review last scan time and high-risk counts, then check Findings and Accounts for newly privileged or dormant privileged accounts. |
| Targeted investigation | Open Assets, find the host/database, open Asset Detail, review accounts and findings, then open Account Detail for evidence. |
| Failed scan troubleshooting | Open Scans, select the job, review target error bucket/detail, fix credential/network/platform issue, then use Retry failed. |
| Remote network scanning | Open Agent Connectors, generate token, deploy agent in the target network, approve it, confirm heartbeat, then launch the scan. |
| Password policy review | Launch a scan with Collect password policies enabled, then open Password Policy to review findings, exceptions, and exports. |
| Rules tuning | Review Account Detail rule matches, update Rules if needed, rerun the relevant scan profile, then confirm Findings/Accounts changed as expected. |
| Audit/compliance evidence | Use Audit Log for operator actions, Password Policy export for policy evidence, and Account Detail evidence for account-specific decisions. |

## Scan Output Interpretation

| Output area | Meaning | Operator action |
|---|---|---|
| Job status | Overall scan lifecycle: pending, queued, running, success, partial success, failed, timed out, unreachable, auth failed, or cancelled. | Monitor status and act on failures. |
| Target status | Per-asset result inside one scan job. | Use target error detail to fix credentials, firewall, collector, or platform configuration. |
| Accounts discovered | Number of identities found on the target. | If unexpectedly low, validate target credentials and collector permissions. |
| Entitlements | Groups, roles, grants, sudo rules, local group membership, service run-as, task run-as, or ACL permissions. | Validate whether the entitlement explains the classification. |
| Rule matches | Classification rules that matched the account. | Use this to explain full admin, delegated admin, privileged service, or sensitive non-admin results. |
| Evidence summary | Raw or normalized data returned by the collector. | Use for audit support and troubleshooting false positives. |
| Password policy findings | Weak password or account policy conditions. | Remediate policy or create approved exception if business-accepted. |

## Operational Notes

- Assets must be discovery-enabled before they are included in Launch All Enabled scans.
- Scan profiles with an empty platform list scan all platforms.
- Scan profiles with platform values skip assets outside that platform scope.
- Password policy collection is opt-in because it adds extra target commands and some platforms provide partial evidence.
- Use Retry failed only after correcting the root cause.
- Use Exceptions to document accepted risk; do not delete evidence to hide known approved accounts.
- Use Audit Log to prove who launched scans, changed rules, approved agents, or exported reports.
- Use connector agents for remote or segmented networks. The connector should call home outbound over HTTPS; the console should not require inbound access into restricted zones.
